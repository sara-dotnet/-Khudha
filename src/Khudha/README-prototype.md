# خُضها — رحلة التجربة الأولى

> تحديث التعريف بالتخصص والمسارات: تعليمات النسخة الحالية في
> `README-journeys.md`. الوصف التالي يوثق الدفعة الأولى التي كانت تقتصر على تطوير المواقع.

هذه الملفات تُضاف إلى مشروع ASP.NET الموجود في `src/Khudha`.
تستخدم قاعدة `KhudhaPrototype` والجداول التي أُنشئت بملف `docs/khudha-schema.sql`.
لا تستبدل ملف المشروع `Khudha.csproj` أو إعداداته المحلية.

## ما تنفذه هذه الدفعة

- اختيار المرحلة والمجال المتاح وعرض تعريف التجربة.
- استرجاع مراجع المجال والقالب من SQL Server وإرسالها إلى Gemini.
- توليد المهمة مع معايير الفريق الثابتة؛ وإظهار مصدر المهمة إذا استُخدم قالب بديل.
- محادثة تلميحات تتلقى المهمة الحالية والمراجع ومسودة الطالب.
- حفظ المحاولة قبل طلب مراجعتها، وحفظ المراجعة بعد التحقق من صيغتها.
- إعادة مراجعة المحاولة المحفوظة عند فشل الوكيل.
- حساب التقدم من المهام المكتملة في قاعدة البيانات.
- استرجاع التجربة في المتصفح نفسه، ونقل الكود المقبول إلى المهمة التالية.

تستهدف هذه الدفعة مسار تطوير المواقع لتثبيت رحلة كاملة أولاً. ما زال ترشيح
المجالات للمتردد، وتوسيع المحتوى إلى مجالات أخرى، وتبديل الأدوار داخل المشاريع
من الأعمال المتبقية. لا يوجد تسجيل حسابات؛ تُستخدم جلسة مجهولة محفوظة بملف
ارتباط محمي. المراجعة إرشادية وليست تقييماً أكاديمياً أو مهنياً نهائياً.

## التشغيل

بعد نسخ الملفات، ومن مجلد المشروع:

```powershell
dotnet build
dotnet run --urls "http://localhost:5050"
```

افتح `http://localhost:5050`.

تقرأ الشيفرة القيم المحلية الموجودة في User Secrets:

- `ConnectionStrings:Khudha`
- `Gemini:ApiKey`
- `Gemini:Model` — النموذج الذي نجح اختباره: `gemini-3.5-flash-lite`.

لا تضف قيمة المفتاح إلى هذه الملفات أو إلى GitHub.

## اختبارات فعلية مطلوبة على جهاز الفريق

1. مسار عادي: اختر خريج ثانوي، ابدأ التجربة، ولّد مهمة، اسأل الوكيل،
   ثم أرسل عنواناً وفقرة مناسبين. تحقق من حفظ المراجعة والتقدم بعد تحديث الصفحة.
2. تحدٍ: أرسل عنواناً فقط. تحقق من ذكر الفقرة الناقصة وعدم احتساب المهمة مكتملة.
3. فشل: جرّب إرسال مدخل مطلوب فارغاً، وتحقق من التنبيه. وعند تعذر خدمة
   المراجعة تحقق من بقاء نص المحاولة وإمكان إعادة المراجعة دون احتساب تقدم وهمي.

لم تُسجل هذه السيناريوهات كنتائج ناجحة مسبقاً. يلزم تشغيلها مع SQL Server
وGemini على جهاز الفريق، وتسجيل النتيجة الفعلية.

فحص صيغة JavaScript والربط بين عناصر HTML أُنجز قبل النقل. لم يُشغّل بناء
C# أو اختبار المتصفح الكامل في بيئة إعداد هذه الحزمة؛ يتحقق منهما الفريق عند التشغيل.

## ملاحظة النشر

عنوان localhost محلي. النشر برابط خارجي يتطلب استضافة تدعم .NET وقاعدة SQL
يمكن للخادم الوصول إليها، مع ضبط إعدادات البيئة بدلاً من User Secrets المحلية.
يجب التحقق من الرابط في نافذة خفية قبل التسليم وتصوير رحلة تعمل فعلياً.
