# خُضها — التعريف بالتخصص والمسارات ثم التجربة العملية

## إصلاح ثبات المراجعة والمهام

- تصبح الإجابة للقراءة فقط أثناء إرسال طلب المراجعة، وتتاح مجدداً إذا كانت المحاولة ناقصة.
- عند اكتمال المهمة تُعرض الإجابة المقبولة من الخادم، وتستبدل أي مسودة محلية قديمة مختلفة.
- يمنع الخادم محاولة جديدة على مهمة مكتملة أو مهمة أقدم، مع بقاء إعادة الطلب بالمعرف نفسه آمنة.
- يفضل استرجاع المراجعة المقبولة للمهمة المكتملة حتى لو وُجد سجل متأخر غير مقبول من نسخة سابقة.
- العنوان والتعليمات والأرقام والمطلوب والمعايير تؤخذ من قالب واحد ثابت. لا يعيد AI صياغتها.
- يكتب الوكيل تلميحاً قصيراً، ويعمل الشات والمراجعة بالاتصال الحقيقي كما سبق. يعرض مصدر المهمة بوضوح.
- ترفض التلميحات التي تضيف أرقاماً أو توجه المستخدم إلى HTML خارج مسار المواقع، ويستخدم التلميح المحضر بدلاً منها.
- لا يتكرر السؤال المحفوظ عند إعادة شات المهمة بعد فشل الرد.
- تزامن قوالب المهام في SQL مع الكتالوج عند التشغيل، دون تغيير المهام الممنوحة أو محاولاتها المحفوظة.
- يتوفر فحص داخلي للخادم عبر `--self-test`، دون طلب SQL أو Gemini.

## تحديث ربط الثانوي والدرس قبل المهمة

- الثانوي في علوم الحاسب يبدأ بتجربة المدخلات والخطوات والتحقق والاختبار.
- الثانوي في إدارة الأعمال يبدأ بتجربة العميل والمشكلة والقيمة والخطة والمتابعة.
- يضاف درس قصير ومثال توضيحي بسياق مختلف وخطة مهام وآلية المراجعة لكل تجربة.
- التجربة الجديدة ثلاث مهام فقط، وتنتهي بإكمالها دون إنشاء مهمة رابعة.
- يظهر طلب أول مهمة مع معرف الدرس الذي اطلع عليه المستخدم، ويُتحقق من تطابقه مع التجربة.
- يتحقق الخادم من تطابق التخصص والمسار مع الجلسة والمهام المحفوظة قبل التوليد أو المراجعة.
- إذا كانت الجلسة القديمة تربط تخصصاً بمهام مواقع، تظهر «ابدأ التجربة الصحيحة».
  ينشئ الزر جلسة صحيحة؛ تبقى السجلات القديمة في قاعدة البيانات دون حذف.
- إذا أعاد مولد المهام محتوى HTML لتجربة أخرى، يُرفض ويستخدم القالب المناسب مع توضيح مصدره.
- أمثلة المراجعة البرمجية محصورة بمسار المواقع، وتختلف أمثلة المراجعة للمجالات الأخرى.

التخصصان المتاحان: **علوم الحاسب** و**إدارة الأعمال**. الكتابة في خانة التخصص
للبحث بينهما؛ لا يبدأ النموذج تجربة لتخصص غير مجهز.

| المرحلة | الرحلة |
|---|---|
| طالب ثانوي أو خريج | اختيار التخصص، تعريف للمبتدئ، شات للاستفسار، ثم «جهّز مهمتي الأولى» |
| طالب جامعي أو خريج | اختيار التخصص، التعرف على مساريه ومقارنتهما بالشات، اختيار مسار، ثم أول مهمة |

| التخصص | مسارات الجامعي |
|---|---|
| علوم الحاسب | تطوير المواقع، وتحليل البيانات |
| إدارة الأعمال | التسويق، وإدارة العمليات |

يوجد تعريف مبسط ومثال واقعي وطريقة بدء لكل تخصص. التجربة التمهيدية لعلوم
الحاسب تتناول المدخلات والخطوات والمخرجات والتحقق والاختبار، دون اشتراط لغة
برمجة. تجربة إدارة الأعمال تتناول العميل والمشكلة والقيمة وتنظيم الموارد
ومتابعة نتيجة مشروع خيالي. المهام في المسارات الأربعة مرتبطة بالمسار المختار.

المحتوى يشمل **ست تجارب عملية**: تجربتان تمهيديتان وأربعة مسارات. لكل تجربة
ثلاثة قوالب متدرجة، بإجمالي **18 قالباً**. المساران في كل تخصص أمثلة متاحة
في النموذج، وليسا حصراً لجميع فروعه أو خطة دراسية معتمدة.

## البيانات ودور AI

- المحتوى التعريفي والقوالب والمراجع في `Content/catalog.json`.
- عند أول تحميل للتخصصات يضيف التطبيق المحتوى الناقص إلى Fields وFieldReferences
  ويزامن TaskTemplates مع الكتالوج داخل معاملة واحدة. لا يحذف بيانات ولا يغير المحاولات أو المهام الممنوحة سابقاً.
- لا يحتاج مخطط SQL جديداً. يحفظ التخصص والمسار في DiscoveryAnswersJson الموجود في Sessions.
- يبدأ الجامعي دون FieldId حتى يختار المسار؛ المخطط السابق يسمح بالقيمة NULL.
- تحفظ رسائل الاستكشاف في Messages مع TaskId فارغ، وتبقى رسائل كل مهمة مرتبطة بمهمتها.
- يعمل شات الاستكشاف عبر Gemini قبل وجود مهمة، ولا يختار المسار نيابة عن الطالب.
- يقدم Gemini التلميح والمحادثة والمراجعة وفق المهمة ومعاييرها المحفوظة، بينما تبقى شروط المهمة وأرقامها ثابتة.
- عند تعذر التوليد يظهر قالب بديل مع توضيح مصدره. لا تستبدل المحادثة أو المراجعة بردود AI وهمية.
- بعد بدء المهام يتطلب تغيير المسار بدء تجربة جديدة، لحماية تسلسل التجربة الحالية.
- الجلسات القديمة دون تخصص تظل قابلة للاسترجاع. يعرض الكود والنص باستخدام textContent.

## التركيب

أوقف الموقع بواسطة Ctrl+C في تيرمنال تشغيله، ثم نفذ:

```powershell
Expand-Archive -LiteralPath "$env:USERPROFILE\Downloads\khudha-core-fix.zip" -DestinationPath "D:\khudha\-khudha\-khudha\src\Khudha" -Force -ErrorAction Stop
dotnet run --project "D:\khudha\-khudha\-khudha\src\Khudha\Khudha.csproj" -- --self-test
if ($LASTEXITCODE -eq 0) {
    dotnet run --project "D:\khudha\-khudha\-khudha\src\Khudha\Khudha.csproj" --urls "http://localhost:5174"
}
```

افتح http://localhost:5174 وحدث بواسطة Ctrl+F5. ابدأ تجربة جديدة لفحص الرحلة
المعدلة. لا تتطلب الحزمة مكتبات إضافية أو إعادة ضبط مفاتيح User Secrets.
لا تستبدل Khudha.csproj أو إعدادات الاتصال. أبق مجلد Content مع التطبيق عند نشره.

## ما فُحص فعلياً

أُنجز فحص صيغة JavaScript وربط معرّفات HTML وبنيته، وسلامة الكتالوج وحدود
النصوص في قاعدة البيانات. كما نجحت اختبارات منطق الواجهة باستخدام DOM وAPI
محاكيين لجميع الرحلات الست. شملت قصر التخصصات على اثنين، ومنع بدء مهام
الجامعي قبل اختيار المسار، وإتاحة الشات قبل المهام، وحفظ الاختيار والمحادثة،
وفشل الشات وإعادة إرساله، والعرض الآمن للنص، وحفظ مسودة المهمة، وإعادة
المراجعة بالمعرف نفسه، والتقدم والتوافق مع الجلسات السابقة. أضيفت اختبارات
واجهات للجلسة القديمة للثانوي في كلا التخصصين، وإظهار الدرس والمثال وعدد
المهام، وعدم إرسال طلب مهمة رابعة بعد إكمال الثلاث.

نجحت كذلك فحوص منطق واجهة خاصة بتثبيت النص أثناء المراجعة، واسترجاع الإجابة
المقبولة رغم وجود مسودة مختلفة، وتحديث تبويب قديم عند رفض محاولة متأخرة،
وإتاحة تعديل الإجابة الناقصة، وإعادة شات المهمة دون تكرار السؤال.

أضيف `KhudhaSelfTests.cs` ويعمل بالأمر أعلاه على جهاز الفريق: يقرأ الكتالوج
الحقيقي ويفحص ثبات القوالب الثمانية عشر وحدود التلميح، ومنع مراجعة مهمة
مكتملة أو قديمة، والتعامل مع السؤال المعلق. لا يستدعي قواعد البيانات أو Gemini.
هذا الفحص لم يُنفذ في بيئة إعداد الحزمة لعدم وجود .NET فيها؛ مخرجاته على جهاز
الفريق هي الدليل على نجاح البناء والفحوص الداخلية. يظل اختبار التكامل الحي مطلوباً.

لم يشغل بناء C# أو متصفح فعلي أو SQL Server أو Gemini في بيئة تجهيز هذه
الحزمة. يجب تأكيد البناء والتكامل الحي على جهاز الفريق؛ الاختبارات المحاكية
ليست دليلاً على ردود AI حقيقية.

أُرفق `Test-LearningRoutes.ps1` لفحص ربط الرحلات الست ودروسها على الخادم
المحلي الحقيقي بعد تشغيله. ينشئ ست جلسات اختبار مجهولة ومعزولة عن متصفحك،
ولا يستدعي Gemini أو ينشئ مهام أو محاولات. هذا الفحص لم يُشغّل في بيئة إعداد
الحزمة لعدم وجود خادم الفريق وقاعدة بياناته فيها.

لتشغيل محتواه في تيرمنال أوامر بعد تشغيل الموقع، دون تغيير سياسة تشغيل السكربتات:

```powershell
& ([scriptblock]::Create((Get-Content -LiteralPath "D:\khudha\-khudha\-khudha\src\Khudha\Test-LearningRoutes.ps1" -Raw)))
```

## فحص حي بعد التركيب

1. اختر الثانوي وعلوم الحاسب. تأكد من ظهور التعريف الكامل قبل المهام، واسأل
   «ما معنى الخوارزمية؟ أعطني مثالاً»، ثم جهز أول مهمة. المتوقع تجربة نصية في التفكير الحاسوبي.
2. ابدأ تجربة جامعية في إدارة الأعمال. اسأل عن الفرق بين التسويق والعمليات
   قبل الاختيار. اختر التسويق وحدث الصفحة؛ تأكد من بقاء الاختيار والشات، ثم ابدأ المهمة.
3. جرب سؤالاً فارغاً، ومحاولة ناقصة ثم مكتملة. عند تعذر AI تحقق من حفظ السؤال
   أو المحاولة وإمكان إعادة الطلب دون ادعاء نجاح غير حقيقي.

## واجهات الربط الجديدة

- GET /api/catalog: التخصصان ومحتواهما ومساراتهما، وتهيئة المحتوى الناقص.
- POST /api/session: بدء جلسة باستخدام stage وmajorSlug.
- POST /api/session/chat: سؤال عن التخصص أو مساراته دون اشتراط مهمة.
- POST /api/session/track: حفظ مسار تابع للتخصص قبل بدء المهام.
- تستمر واجهات الجلسة والمهام والمحاولات والتلميحات السابقة.
